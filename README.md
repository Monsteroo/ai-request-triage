# Тріаж вхідних запитів AI-юніту

Внутрішні команди пишуть в AI-юніт у вільній формі — у Slack, Telegram, поштою.
Перш ніж брати запит у роботу, його треба зрозуміти: про що він, чий, наскільки
терміново і чи взагалі можна за нього братися як є.

Цей сервіс читає вивантаження такого інбоксу, проганяє кожен запит через LLM,
**валідує відповідь у строгу схему** і віддає структурований `output.json` та
зведений `report.md` з чергою на уточнення.

```
CSV → нормалізація → [async, з обмеженням частоти] → LLM (structured output)
                                                       │
                             ┌─────────────────────────┴─── помилка
                             │                              │
                        валідація                    ретрай / repair-промпт
                             │                              │
                      бізнес-правила              запис зі status="failed"
                             │                              │
                             └──────────┬───────────────────┘
                                        ▼
                            output.json  +  report.md
```

**Головна властивість: кожен вхідний рядок дає рівно один вихідний запис.**
Запит може не обробитися — модель здатна намолоти дурниць, API повернути 429,
мережа відвалитися — але зникнути він не може. Помилки це теж дані: вони
лягають у результат зі `status="failed"`, причиною і останньою сирою відповіддю
моделі.

## Швидкий старт

### Без API-ключа

Весь пайплайн можна прогнати офлайн на детермінованому стабі — щоб подивитися,
як воно влаштоване, ключ не потрібен:

```bash
python -m venv .venv && ./.venv/bin/pip install -r requirements.txt
PYTHONPATH=src ./.venv/bin/python -m triage --provider fake
```

Стаб — це матчер за ключовими словами, а не класифікатор. Він ніколи не
підставляється замість справжнього провайдера мовчки: `fake` треба попросити
явно, щоб ніхто не переплутав вивід заглушки з виводом моделі.

### З Gemini

```bash
cp .env.example .env     # і вписати GEMINI_API_KEY
PYTHONPATH=src ./.venv/bin/python -m triage
```

Безкоштовний ключ береться за хвилину в [Google AI Studio](https://aistudio.google.com/apikey).
Картка не потрібна. `.env` у `.gitignore`.

### Docker

```bash
docker build -t request-triage .
docker run --rm --env-file .env -v "$(pwd)/output:/app/output" request-triage
```

## Конфігурація

Усе читається з оточення (або з `.env`), прапорці CLI мають пріоритет.

| Змінна | Прапорець | Дефолт | Навіщо |
|---|---|---|---|
| `LLM_PROVIDER` | `--provider` | `gemini` | `gemini` або `fake` |
| `GEMINI_API_KEY` | — | — | ключ; у репозиторій не потрапляє |
| `GEMINI_MODEL` | `--model` | `gemini-3.5-flash` | запінено навмисно, див. нижче |
| `GEMINI_THINKING_BUDGET` | — | `0` | `0` — без «мислення», `auto` — на розсуд моделі |
| `MAX_CONCURRENCY` | `--concurrency` | `4` | скільки викликів одночасно |
| `REQUESTS_PER_MINUTE` | `--rpm` | `5` | під квоту free tier; `0` вимикає |
| `MAX_ATTEMPTS` | — | `4` | спроб на один запит |
| `REQUEST_TIMEOUT_S` | — | `60` | таймаут одного виклику |
| — | `--input` | `data/input_requests.csv` | вхідний файл |
| — | `--outdir` | `output` | куди писати результат |
| — | `--limit` | — | обробити лише перші N (дешевий смоук-тест) |

Коди виходу: `0` — усе оброблено, `2` — завершилось, але є невдалі рядки,
`1` — запуск не відбувся. Це щоб сервіс можна було поставити в cron чи CI.

## Що на виході

**`output.json`** — об'єкт, а не голий масив: поруч із даними лежить
провенанс прогону (коли, якою моделлю, скільки токенів, скільки помилок).
Голий масив каже, що вирішили, але не каже ким і якою ціною — а це саме те,
що хочеться знати, коли два прогони розійшлися.

```jsonc
{
  "schema_version": "1.0.0",
  "generated_at": "...",
  "provider": "gemini",
  "model": "gemini-3.5-flash",
  "stats": { "total": 18, "ok": 18, "failed": 0, "prompt_tokens": ... },
  "requests": [
    {
      "id": "REQ-001", "channel": "Slack", "status": "ok",
      "triage": {
        "category": "звіт/аналітика",
        "target_department": "маркетинг",
        "priority": "medium",
        "short_summary": "...",
        "requested_actions": ["..."],
        "needs_clarification": false,
        "confidence": 0.9,
        "clarifying_questions": [],
        "mentioned_systems": ["Google Ads"],
        "is_actionable": true
      },
      "error": null,
      "meta": { "attempts": 1, "applied_rules": [], "prompt_tokens": 1757 }
    }
  ]
}
```

**`report.md`** — агрегати по категоріях, пріоритетах і відділах, окремо черга
на уточнення (з конкретними питаннями до замовника), список високопріоритетних,
список невдалих і перелік спрацьованих бізнес-правил.

## Схема

Шість полів — обов'язкові за завданням. Ще чотири я додав; кожне мусить
виправдати своє існування конкретним рядком із наданого інбоксу, інакше це
просто зайві токени:

| Поле | Навіщо | Приклад із даних |
|---|---|---|
| `confidence` (0–1) | напарник до `needs_clarification`: дозволяє автоматично відправляти на людину все, у чому модель невпевнена, навіть якщо вона сама цього не визнала | пороговане правилом R3 |
| `clarifying_questions` | «розмито» — це діагноз, а не дія. Питання перетворюють прапорець на наступний крок, який можна одразу відправити замовнику | REQ-002 «хлопці треба бот», REQ-011 «нам би табличку якусь» |
| `mentioned_systems` | роутинг на інженера, який знає цю систему, і оцінка, які інтеграції потрібні | PlanFix, BigQuery, Google Ads, Meta — трапляються у 10 із 18 запитів |
| `is_actionable` | відсікає те, що взагалі не одиниця роботи, не змішуючи це з «поза скоупом за темою» | REQ-008 «дякую за вчора 🙌» |

## Рішення, які варто пояснити

**Категорії перетинаються, тому в промпті зафіксований каскад.**
«Автоматизувати щотижневий звіт» (REQ-001) — це чесно і автоматизація, і
звітність. Замість того щоб робити вигляд, ніби існує одна правильна відповідь,
задано явний порядок пріоритету: поза скоупом → баг → консультація → інтеграція
→ звіт → автоматизація. Це продуктове рішення, а не істина, але воно робить
вивід відтворюваним, а агрегати — порівнюваними між прогонами. Порядок лежить
в одному місці й міняється за хвилину.

**Словники закриті.** `category`, `priority` і `target_department` —
переліки, а не вільні рядки. Вільний рядок дав би «маркетинг», «Маркетинг»,
«відділ маркетингу» і «marketing» як чотири різні відділи, і звіт розсипався б.
Значення підставляються в промпт із тих самих Python-перелічень, якими потім
валідуються, тож промпт і валідатор не можуть розійтися.

**Structured output і pydantic — обидва, не один.** Схема на боці API прибирає
цілий клас багів (модель загорнула JSON у ```-огорожу). Але вона не вміє в
міжпольові правила, і провайдер без цієї фічі мовчки забрав би гарантію. Тому
жорсткі ворота — все одно pydantic, з `extra="forbid"`.

**Бізнес-правила окремо від валідації.** Валідація відповідає на питання
«чи коректно сформовано». Правила — на питання «чи не суперечить воно саме
собі»: модель уміє повернути ідеально типізований об'єкт, у якому
`needs_clarification=false` стоїть поруч із `confidence=0.2`. Кожне спрацювання
пишеться в `meta.applied_rules`, тож сира думка моделі завжди відрізняється від
нашої постобробки.

**Few-shot приклади — синтетичні.** Вони покривають форми, на яких модель
спотикається (порожній запит, подяка, два прохання в одному повідомленні), але
жоден не взятий із реального інбоксу — інакше я б просто підказав відповіді на
той самий файл, на якому потім і міряю якість.

**Модель запінена, а не через аліас.** `gemini-flash-latest` змінюється під
тобою — при тому, що весь сенс `temperature=0` і фіксованого `seed` у
відтворюваності. Дрібниця, яка коштувала часу: ендпоінт `models.list` віддає
моделі, які потім 404-ляться для нових ключів (`gemini-2.5-flash`), а
`gemini-2.0-flash` уже виведений з обігу зовсім.

**Запит — це дані, а не інструкції.** `raw_text` пишуть люди, і REQ-014 уже
містить URL. Текст обгортається явними маркерами, а в системному промпті сказано
не виконувати вказівок ізсередини й не ходити за посиланнями.

## Тести

```bash
./.venv/bin/pip install -r requirements-dev.txt
./.venv/bin/python -m pytest -q
```

Мережі не торкаються, ключа не потребують, час замокано — уся сюїта менш ніж
за секунду. Найцікавіше в ній не щасливий шлях, а шляхи відмови: биті JSON,
порушення схеми, 429, таймаути й мертвий ключ не повинні призводити до втрати
рядка чи до безглуздих ретраїв.

## Структура

```
src/triage/
  models.py      словники + строга схема + нормалізація вивертів моделі
  rules.py       детерміновані бізнес-правила поверх валідації
  reader.py      читання CSV (BOM, порожні рядки, дублі, биті дати)
  prompts.py     системний промпт, few-shot, repair-промпт
  pipeline.py    async-оркестрація, rate limiter, ретраї, гарантія 1-до-1
  report.py      output.json + report.md
  config.py      налаштування з оточення, вибір провайдера
  cli.py         точка входу
  llm/
    base.py      LLMClient ABC + типізовані помилки
    gemini.py    Gemini: structured output, temperature 0, seed, retry-hint
    fake.py      офлайн-стаб для тестів і демо
```
