# Живе демо тріажу

Сторінка, де можна вписати довільний запит і побачити, як пайплайн із цього
репозиторію його класифікує. Дошка внизу заповнена **реальним виводом** прогону
(18/18 без помилок), а не вигаданими прикладами.

Адреса: `testwork-netpeak.vitaliimaslii.com`

---

## Як це влаштовано

Один Cloudflare Worker робить обидві роботи:

| Шлях | Що робить |
|---|---|
| `/` | віддає `public/index.html` + `public/app.js` через `[assets]` |
| `/data/baseline.json` | 18 запитів реального прогону |
| `POST /api/triage` | класифікує новий запит через ланцюжок провайдерів |
| `POST /api/telegram` | надсилає щойно класифікований запит у бота |

Сторінка й API на одному походженні, тому CORS не потрібен узагалі.

**Промпт і схема не пишуться руками.** Вони генеруються з Python-коду
(`scripts/export_worker_contract.py`) у `worker/generated/contract.js`, тож
Worker і пайплайн не можуть розійтися. Оркестрація — інша річ: тут одна
повторна спроба на провайдер і без repair-промпта, бо логіка Python
розрахована на цілу пачку, а не на один веб-запит. Це написано й на самій
сторінці.

**Класифікація йде ланцюжком провайдерів** (`worker/providers.js`): Gemini
першим, і якщо він вичерпав безкоштовну квоту (429) або не налаштований —
запит автоматично йде на Groq (`gpt-oss-120b`), далі на Cerebras
(`gpt-oss-120b`). Обидва — безкоштовні хости моделі, яку опублікувала OpenAI;
сам OpenAI цю модель безкоштовно не роздає. Кожен провайдер повертає лише
сирий текст — валідація (`validate.js`) та сама для всіх, тож дешевша
`json_object`-схема замість специфічного для кожного провайдера structured
output — свідомий компроміс: менше шансів на розбіжність між незнайомими API,
а справжні ворота все одно pydantic-подібна перевірка на боці Worker. Досить
налаштувати хоча б один секрет — решта підключаються, коли з'являться їхні
ключі.

**Дошка сортує кожну колонку** за пріоритетом (high → medium → low), а в
межах пріоритету — запити, що потребують уточнення, спливають вище (логіка в
`public/app.js`, `sortColumn`). Свій запит можна позначити галочкою — він
переїде у 7-му колонку «Виконано». Чекбокс є лише на картках, доданих через
форму: 18 базових карток — це незмінний знімок реального прогону, а не
список справ.

## Перезбірка даних після нового прогону

```bash
python -m triage                          # новий прогін пайплайна
python scripts/export_web_data.py         # output.json  → web/public/data/baseline.json
python scripts/export_worker_contract.py  # промпт+схема → web/worker/generated/contract.js
```

## Тести

```bash
cd web && npm test
```

Мережі не торкаються. Перевіряють те, що ламається тихо: валідацію відповіді
моделі (вигадана категорія, `confidence` поза діапазоном, зайве поле, битий
JSON) і лічильники лімітів, зокрема поведінку при недоступному KV.

## Локальний запуск

```bash
cd web
npx wrangler dev
```

Без секретів `/api/triage` чесно поверне 503 — сторінка й дошка працюватимуть.

## Що треба зробити руками (я не маю доступу до цих кроків)

### 1. KV для лічильників — ✅ вже зроблено

Namespace створений, його `id` уже стоїть у `wrangler.toml`. Якщо колись
знадобиться новий:

```bash
cd web && npx wrangler kv namespace create RATE_LIMITS
```

### 2. Ключі моделей — Gemini обов'язковий, Groq/Cerebras опційні

Демо працює з хоча б одним налаштованим ключем; кожен наступний — це
резервний провайдер.

```bash
npx wrangler secret put GEMINI_API_KEY      # https://aistudio.google.com/apikey
npx wrangler secret put GROQ_API_KEY        # https://console.groq.com/keys — опційно
npx wrangler secret put CEREBRAS_API_KEY    # https://cloud.cerebras.ai/ — опційно
```

Усі три — безкоштовні тіри, картка не потрібна. Порядок ланцюжка фіксований
у коді: Gemini → Groq → Cerebras.

### 3. Telegram (опційно — без нього кнопка просто неактивна)

1. Написати [@BotFather](https://t.me/BotFather) → `/newbot` → отримати токен.
2. Написати своєму боту будь-що, потім відкрити
   `https://api.telegram.org/bot<ТОКЕН>/getUpdates` і взяти `chat.id`.

```bash
npx wrangler secret put TELEGRAM_BOT_TOKEN
npx wrangler secret put TELEGRAM_CHAT_ID
```

### 4. Деплой

```bash
npx wrangler deploy
```

### 5. Субдомен

У дашборді Cloudflare: **Workers & Pages → testwork-netpeak → Settings →
Domains & Routes → Add → Custom domain** → `testwork-netpeak.vitaliimaslii.com`.
DNS-запис Cloudflare створить сам, бо домен уже в тому ж акаунті.

## Ліміти

Публічна сторінка з живим ключем, тому:

| Що | Значення | Навіщо |
|---|---|---|
| класифікацій з однієї IP | 15 / добу | щоб один відвідувач не з'їв квоту |
| класифікацій усього | 120 / добу | стеля, що захищає саму квоту Gemini |
| надсилань у Telegram з IP | 5 / добу | щоб демо не стало спам-каналом |
| довжина запиту | 1000 символів | обмежує вартість токенів |

Значення — у `worker/index.js`, константа `LIMITS`.

---

## Відомі обмеження

- **Worker — спрощений двійник, а не той самий код.** Контракт спільний,
  оркестрація ні. Оригінал із ретраями, repair-промптом і `RunGuard` — у
  `src/triage/`.
- **Нові запити живуть у `localStorage`** конкретного браузера. Спільного
  стану між відвідувачами немає навмисно: на публічній сторінці він збирав би
  сміття. З тієї ж причини «Виконано» — це теж локальний стан браузера, не
  спільна дошка.
- **KV має eventual consistency.** Паралельні запити можуть проскочити повз
  лічильник на одиниці. Для захисту добової квоти цього достатньо, для
  біллінгу — ні.
- **Ланцюжок провайдерів перевірено юніт-тестами на самій логіці розгалуження**
  (`worker/providers.test.js`), а наскрізно (живим ключем) — лише Gemini. Groq
  й Cerebras використовують той самий, добре відомий OpenAI-сумісний
  `chat/completions`-формат, тож ризик малий, але це вимагає окремих ключів,
  яких я не маю, щоб перевірити самому.
- **Em-dash в українському тексті лишено навмисно.** У копірайтингу
  англійською «—» вважається ознакою тексту, згенерованого LLM; в українській
  це звичайна, граматично коректна пунктуація, і прибирати її означало б
  зробити текст менш природним, а не більш — свідомий відступ від типового
  чек-листа для лендінгів.
